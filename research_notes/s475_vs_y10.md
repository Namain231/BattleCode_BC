# Architectural and Behavioral Comparison: S.4.7.5 vs cand_y10 (Y.10)

This research note documents a comparative analysis between the reference opponent **S.4.7.5** (`opponents/s475/`) and our development baseline **Y.10** (`cand_y10/main.cpp`), specifically targeting three measured loss causes:
1. **Late-Game Longest Dragon Tiebreak & Feeding/Budding** (2–3x total mass advantage lost on length tiebreak; budding until r400 keeping units at 2–4; feeding deadlock requiring queen $\ge 10$; multi-queen feed chains halving mass).
2. **Friendly Head-on Collisions Through Portals** (unseen head-on collisions where drones exit portals directly onto a friendly queen or teammate).
3. **Opening Numbers War on Maze Maps** (pearl eating deficits and population lags on Trophy, Devil, and Trauma).

---

## 1. Late-Game Tiebreak Dominance: Feeding, Queen Designation & Budding

### 1.1 How S.4.7.5 Handles It

S.4.7.5 separates macro dragon roles into **Grower** and **Swarm**, implements an anti-synchronization staggered feed window, caps feeder length to eliminate mass-halving chains, and establishes a single consensual queen sink.

#### Role Distinction & Queen Deference
- **Grower Qualification** ([opponents/s475/policy.hpp:307-310](file:///D:/battlecode/BattleCode_BC/opponents/s475/policy.hpp#L307-L310)):
  ```cpp
  // Policy::isGrower
  bool isGrower(int id, int len) const {
      bool growPhase = w_.t.units >= p_.growerMinUnits || w_.t.round >= p_.growRound;
      return growPhase && (w_.isInitial(id) || len >= p_.promoteLen);
  }
  ```
  `growerMinUnits = 40`, `growRound = 300`, `promoteLen = 10` ([opponents/s475/common.hpp:97-125](file:///D:/battlecode/BattleCode_BC/opponents/s475/common.hpp#L97-L125)). Only initial starting dragons or dragons reaching length $\ge 10$ after round 300 become growers.
- **Queen Deference (Preventing Parallel Growers)** ([opponents/s475/policy.hpp:55-67](file:///D:/battlecode/BattleCode_BC/opponents/s475/policy.hpp#L55-L67)):
  In `Policy::decide()`, if a grower sees a teammate longer by `queenDeferMargin` (2) (`s.visible > L_ + p_.queenDeferMargin && isGrower(...)`) or receives a gossiped queen that is fresher and longer (`w_.knownQueenLen > L_ + p_.queenDeferMargin`), it drops its grower role (`grower_ = false;`). Multiple dragons never compete in parallel as growers.

#### Budding Cutoffs & Length Retention
- **Feed Phase Budding Prohibition** ([opponents/s475/policy.hpp:819](file:///D:/battlecode/BattleCode_BC/opponents/s475/policy.hpp#L819)):
  In `Policy::trySplit()`, `if (w_.t.round >= p_.feedRound) return false;` (`feedRound = 400`). Splitting is strictly forbidden during the feeding phase.
- **Swarm Budding Cutoff** ([opponents/s475/policy.hpp:827-830](file:///D:/battlecode/BattleCode_BC/opponents/s475/policy.hpp#L827-L830)):
  In `Policy::trySplit()`:
  ```cpp
  // Late game: the tiebreak is the longest dragon, so stop splitting and let
  // length pile up, unless the army needs rebuilding.
  if (w_.t.round >= p_.growRound && w_.t.units >= p_.lateSplitUnits) return false;
  ```
  `growRound = 300`, `lateSplitUnits = 20` ([opponents/s475/common.hpp:125-126](file:///D:/battlecode/BattleCode_BC/opponents/s475/common.hpp#L125-L126)). Once round 300 is reached and army units $\ge 20$, the swarm completely stops budding, allowing all surviving dragons to naturally grow thick.
- **Grower Body Retention** ([opponents/s475/policy.hpp:821-824](file:///D:/battlecode/BattleCode_BC/opponents/s475/policy.hpp#L821-L824)):
  Growers stop splitting completely at `midEnd = 400` (`if (lateGame()) return false;`). Before round 400, a grower must retain `keep = growerKeepBase + round / growerKeepEvery` segments (`growerKeepBase = 4`, `growerKeepEvery = 30`; e.g., at round 300, keep is 14 segments; at round 360, keep is 16).

#### Feeding Protocol: Staggered Timing, Feeder Cap & Throughput Throttling
- **Feeder Gate & Staggering** ([opponents/s475/policy.hpp:72-87](file:///D:/battlecode/BattleCode_BC/opponents/s475/policy.hpp#L72-L87)):
  In `Policy::decide()`:
  ```cpp
  int myFeedRound = p_.feedRound + (w_.init.id % std::max(1, p_.feedWindow));
  if (w_.t.round >= myFeedRound && w_.t.round < p_.feedStop && L_ <= p_.feedMaxLen) {
      int bestLen = L_ + p_.feedMargin - 1;
      for (World::Seen const& s : w_.others)
          if (!isEnemy(s) && s.visible > bestLen) {
              bestLen = s.visible;
              feedHead_ = s.head;
          }
      if (feedHead_ < 0) {
          bool queenFresh = w_.knownQueenRound >= 0 && w_.t.round - w_.knownQueenRound <= p_.queenStale;
          if (queenFresh && w_.knownQueenLen > bestLen && w_.knownQueenCell != w_.head)
              feedHead_ = w_.knownQueenCell;
      }
  ```
  - `feedRound = 400`, `feedWindow = 80`, `feedStop = 490` ([opponents/s475/common.hpp:158-169](file:///D:/battlecode/BattleCode_BC/opponents/s475/common.hpp#L158-L169)): Start rounds are staggered per dragon ID (`id % 80`), eliminating synchronised army pile-ups.
  - `L_ <= p_.feedMaxLen` (`feedMaxLen = 6`): **Only dragons of length $\le 6$ are allowed to feed.** Dragons with length $> 6$ do not sacrifice themselves. This structurally prevents feed chains (where mass is halved at every transfer).
  - Target qualification: `bestLen = L_ + feedMargin - 1` (`feedMargin = 4`). A length 2 feeder only requires the queen to have length $\ge 6$. There is **no requirement** that the queen must already be length $\ge 10$.
- **Throughput Jam Prevention** ([opponents/s475/policy.hpp:94-100](file:///D:/battlecode/BattleCode_BC/opponents/s475/policy.hpp#L94-L100)):
  If more than `feedThroughputCap` (2) teammates are within Chebyshev radius `feedThroughputRadius` (4) of the queen, the feeder aborts feeding this turn (`feedHead_ = -1`) and plays normal foraging/safety.
- **Sacrifice Delivery** ([opponents/s475/policy.hpp:105-115](file:///D:/battlecode/BattleCode_BC/opponents/s475/policy.hpp#L105-L115)):
  When within distance `feedDist = 1` of the queen's head, the feeder steps backwards into its own neck:
  ```cpp
  c.dir = w_.t.dir ^ 2;
  c.dest = b.nb[w_.head * 4 + c.dir];
  c.why = "feed";
  c.score = 1e9;
  return c;
  ```
- **Queen Broadcast Single Source** ([opponents/s475/gossip.hpp:67-82](file:///D:/battlecode/BattleCode_BC/opponents/s475/gossip.hpp#L67-L82)):
  In `Gossip::broadcast()`, only dragons acting as growers (`grower == true && length >= 3`) broadcast `T_QUEEN` sonar messages. Feeders and swarm dragons do not broadcast queen status.

### 1.2 How cand_y10/main.cpp Handles It

1. **Budding Persists to Round 400 on Maze Maps** ([cand_y10/main.cpp:1232-1233](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L1232-L1233)):
   ```cpp
   // swarmSplit()
   int until = bigFeed ? 330 : (UNITS < 45 ? 400 : P.budUntil);
   if (ROUND >= until) return false;
   ```
   On maze maps (`bigFeed == false`), `UNITS` typically hovers around 20–35. Because `UNITS < 45` is almost always true, `until` evaluates to `400` regardless of `P.budUntil = 300` ([cand_y10/main.cpp:313](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L313)). Every dragon that reaches length 4 buds off a length 2 child, keeping the entire population at length 2–4 until round 400.
2. **Deadlocked Feeding Gate (Queen $\ge 10$)** ([cand_y10/main.cpp:1354-1356](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L1354-L1356)):
   ```cpp
   // tryFeed()
   int startRound = bigFeed ? 360 : 420;
   if (ROUND < startRound || iAmQueen() || !outranks(queen.len, queen.id) || ROUND - queen.round > 25) return false;
   if (queen.cell < 0 || queen.len < (bigFeed ? 6 : 10)) return false;
   ```
   On maze maps, `tryFeed()` does not activate until round 420, and strictly aborts if `queen.len < 10`. Because budding suppressed all dragons below length 4–6 through round 400, no dragon reaches length 10 organically. A deadlock occurs: drones refuse to feed unless queen $\ge 10$, but queen cannot reach length 10 because drones refuse to feed her. Similarly, queen homing in `think()` ([cand_y10/main.cpp:1483](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L1483)) requires `queen.len >= max(8, MY_LEN + 2)`.
3. **Feeding Chains and Multi-Queen Chaos** ([cand_y10/main.cpp:1320-1344](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L1320-L1344), [1353-1366](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L1353-L1366), [1631-1632](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L1631-L1632)):
   - In `tryFeed()`, there is no feeder length cap (`MY_LEN` can be 8, 12, etc.).
   - In `updateQueen()`, any dragon whose length exceeds `queen.len` declares itself queen (`if (MY_LEN > queen.len ...) queen = me;`).
   - In `castRadar()`, every dragon broadcasts `queen` on all 4 rays.
   - When multiple dragons in isolated pockets eat pearls and reach length 6–8, each claims queen status. Drones feed into 9 different local "queens" (measured in Trauma loss analysis). Worse, a dragon receiving feeds that is outranked by another distant dragon turns around and executes `SPLIT 1` to feed that other dragon, discarding $\lceil L/2 \rceil$ pearls at every step and dissipating team mass exponentially.
4. **Unused Consolidation Parameters**:
   `endFeedFrom = 430` and `endFeedRadius = 25` are declared in `Params` ([cand_y10/main.cpp:56-57](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L56-L57)), but `endFeedFrom` is completely unused throughout `cand_y10/main.cpp`.

### 1.3 Concrete Porting Recommendations for cand_y10/main.cpp

1. **Change 1.1: Enforce Hard Budding Cutoff at Round 300 on Maze Maps**
   - **Location**: [cand_y10/main.cpp:1232](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L1232) in `swarmSplit()`.
   - **Current**:
     ```cpp

     ```
   - **Proposed**:
     ```cpp
     int until = bigFeed ? 330 : (UNITS >= 20 ? P.budUntil : 360);
     ```
   - **Rationale**: Ports S.4.7.5's `lateSplitUnits = 20` and `growRound = 300` logic. Once our unit count reaches 20, budding shuts off at `P.budUntil = 300`, allowing dragons 60–100 rounds of uninhibited feeding to build length 8–16 naturally before feeding commences.

2. **Change 1.2: Lower Queen Feed Threshold and Enable Earlier Maze Feeding**
   - **Location**: [cand_y10/main.cpp:1354-1356](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L1354-L1356) in `tryFeed()`, and [cand_y10/main.cpp:1481-1483](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L1481-L1483) in `think()`.
   - **Current**:
     ```cpp

     if (ROUND < startRound || iAmQueen() || !outranks(queen.len, queen.id) || ROUND - queen.round > 25) return false;

     // think() homing:
     feeding = (ROUND >= P.feedFrom && ... && queen.len >= max(8, MY_LEN + 2) ...);
     ```

   - **Proposed**:
     ```cpp

     if (ROUND < startRound || iAmQueen() || !outranks(queen.len, queen.id) || ROUND - queen.round > 30) return false;

     // think() homing:

     ```
   - **Rationale**: Breaks the deadlock by aligning feeding start round with `P.feedFrom = 360` and requiring only `queen.len >= max(6, MY_LEN + 2)` instead of `10`. A length 2 or 3 drone can immediately start feeding a length 6 queen.

3. **Change 1.3: Eliminate Feed Chains by Capping Feeder Length**
   - **Location**: [cand_y10/main.cpp:1355](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L1355) in `tryFeed()`.

   - **Rationale**: Direct port of S.4.7.5 `feedMaxLen = 6` ([opponents/s475/common.hpp:187](file:///D:/battlecode/BattleCode_BC/opponents/s475/common.hpp#L187)). Dragons of length $\ge 7$ are preserved as secondary giants for the endgame tiebreak, preventing them from being consumed and dropping only half their mass.

## 2. Unseen Portal Collisions: Friendly Head-Ons

### 2.1 How S.4.7.5 Handles It

S.4.7.5 implements three distinct mechanisms to manage blind portal exits:
1. **Blind Portal Step Danger (`wBlind`)** ([opponents/s475/policy.hpp:759-769](file:///D:/battlecode/BattleCode_BC/opponents/s475/policy.hpp#L759-L769)):
   In `Policy::scoreFrom`:
   ```cpp
   // Through a portal the far side may be out of vision. Only the real first step
   // pays for that (lookahead leaves vision all the time), and only much when we
   // recently saw dragons around the exit.
   if (k == 0 && !w_.visible(dest) && dest != b.id(b.X(head) + DX[d], b.Y(head) + DY[d])) {
       bool busy = false;
       for (int q = -1; q < 4 && !busy; q++) {
           int n = q < 0 ? dest : b.nb[dest * 4 + q];
           busy = n >= 0 && w_.occSeen[n] >= 0 && w_.t.round - w_.occSeen[n] <= p_.blindMemory;
       }
       danger += busy ? p_.wBlind * (1.0 + 0.25 * newL) : p_.wBlindQuiet;
   }
   ```
   `wBlind = 2.0`, `wBlindQuiet = 0.3`, `blindMemory = 6` ([opponents/s475/common.hpp:86-88](file:///D:/battlecode/BattleCode_BC/opponents/s475/common.hpp#L86-L88)). If stepping through a portal onto an unseen cell where any dragon was seen occupying the landing tile or its 4 orthogonal neighbors within the last 6 rounds, danger increases substantially by $2.0 \times (1 + 0.25 \times L)$.
2. **Anti-Loitering at Portal Landing Cells (`wPortalLoiter`)** ([opponents/s475/policy.hpp:770-776](file:///D:/battlecode/BattleCode_BC/opponents/s475/policy.hpp#L770-L776)):
   ```cpp
   // Heads parked next to a portal are what dragons coming through it crash into
   // (they cannot see us). Pass through or move on; do not loiter there.
   bool crossing = dest != b.id(b.X(head) + DX[d], b.Y(head) + DY[d]);
   if (k == 0 && b.portalSide[dest] && b.portalSide[head] && !crossing) danger += p_.wPortalLoiter;
   ```
   `b.portalSide[c]` is precomputed in `Board::rebuild()` ([opponents/s475/board.hpp:68](file:///D:/battlecode/BattleCode_BC/opponents/s475/board.hpp#L68)) to mark every cell with a portal on any of its four edges. `wPortalLoiter = 1.0` penalizes pacing or parking next to a portal without crossing it. Dragons (and especially queens) actively avoid lingering in landing zones.
3. **Stigmergic Crowd Memory (`wCrowd`)** ([opponents/s475/world.hpp:190-194](file:///D:/battlecode/BattleCode_BC/opponents/s475/world.hpp#L190-L194), [opponents/s475/policy.hpp:758](file:///D:/battlecode/BattleCode_BC/opponents/s475/policy.hpp#L758)):
   Decaying trail memory (`crowd[c] *= 0.9375f`) repels teammates from paths recently frequented by the team (`danger += p_.wCrowd * w_.crowd[dest]`).
4. *Direct Queen Cell Exclusion through Portals*: **Not found** in S.4.7.5. S.4.7.5 relies on `wBlind` + `wPortalLoiter` + `wCrowd` rather than an explicit `dest == knownQueenCell` check.

### 2.2 How cand_y10/main.cpp Handles It

1. **Blind Portal Steps on Known Maps Treated as Fully Safe** ([cand_y10/main.cpp:1054-1062](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L1054-L1062)):
   In `evaluate()`:
   ```cpp
   if (s.outside) {
       bool remembered = !s.cells.empty() && memExpire[s.cells.back()] > ROUND;
       if (KM && !remembered) score -= (bigFeed ? 0.8 : 2.0) + 0.03 * L;
       else { score -= 3.0 + 0.12 * (L + P.deathExtra); e.safeClass = 0; }
   }
   // ...
   bool riskOk = e.pDeath < 0.25 || miner || (cheap && !bigFeed && e.pDeath < 0.9);
   e.safeClass = (riskOk && !adjacentThreat && (!s.outside || (KM && e.safeClass > 0))) ? 1 : 0;
   ```

   On any recognized map (`KM != nullptr`, e.g., Default or Portals), stepping through a portal outside the 7x7 vision window only subtracts a negligible 2.0 score penalty and explicitly retains `safeClass = 1`. Any small drone will happily jump through portals blindly.
2. **Friendly Head Proximity (`zoneF`) Does Not Cross Portals** ([cand_y10/main.cpp:571-578](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L571-L578)):
   ```cpp

       if (dr.headCell < 0) continue;
       for (int d = 0; d < 4; d++) {
           int n = nbr[dr.headCell * 4 + d];
           if (n < 0) continue;
           if (dr.team == MY_TEAM) zoneF[n] = 1; else zoneE[n] = 1;
       }
   }
   ```
   `dr.headCell` is populated only from visible parts in `V.parts`. Because vision is strictly bounded to 7x7 and does not penetrate portals, a friendly dragon or queen sitting on the other side of a portal has `zoneF = 0`.
3. **No Gossiped Queen Exclusion on Portal Exits**:
   Even though `queen.cell` is continually updated via 4-way sonar telemetry ([cand_y10/main.cpp:1320-1344](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L1320-L1344)), neither `simulate()` nor `evaluate()` checks whether a portal landing tile is on or adjacent to `queen.cell`.
4. **No Portal Landing Loitering Avoidance**:
   Queens and high-value dragons have no awareness of portal landing tiles. In match replays (e.g. Default vs S.4.7.5 r480), queen 176 parked motionless directly on a portal exit cell and was killed when drone 209 stepped through the portal 20 tiles away.

## 3. Opening Numbers War on Maze Maps (Trophy, Devil, Trauma)

### 3.1 How S.4.7.5 Handles It

S.4.7.5 wins the opening numbers war through **round 0 map matching**, **high-yield fountain swarming without self-inhibition**, **macro compass navigation**, and **uninhibited swarm budding**.

#### Instant Map Resolution via Spawn Coordinates
- **Round 0 Filter** ([opponents/s475/knownmap.hpp:57-74](file:///D:/battlecode/BattleCode_BC/opponents/s475/knownmap.hpp#L57-L74), [80-88](file:///D:/battlecode/BattleCode_BC/opponents/s475/knownmap.hpp#L80-L88)):
  `KnownMapMatcher::filterBySpawn(w)` checks our starting head position against candidate spawn tables `m.spawns`. Because start positions are distinct, the map is resolved on round 0 without needing to inspect walls or wait for vision.
- **Immediate Fountain Activation** ([opponents/s475/knownmap.hpp:160-167](file:///D:/battlecode/BattleCode_BC/opponents/s475/knownmap.hpp#L160-L167)):
  All known pearl beds are marked with `cdObs[c] = 99`. In `Policy::buildTargets()` ([opponents/s475/policy.hpp:386-401](file:///D:/battlecode/BattleCode_BC/opponents/s475/policy.hpp#L386-L401)), any bed with `cdObs >= 99` is considered certain and added to `hot_` immediately from round 0.

#### Fountain Swarming and Teammate Yielding Discipline
- **Local Yielding Only (`hotYield = 4`)** ([opponents/s475/common.hpp:205](file:///D:/battlecode/BattleCode_BC/opponents/s475/common.hpp#L205), [opponents/s475/policy.hpp:650-652](file:///D:/battlecode/BattleCode_BC/opponents/s475/policy.hpp#L650-L652)):
  In `Policy::scoreFrom`:
  ```cpp
  for (Hot const& h : hot_) {
      int dd = dist[h.cell];
      if (dd == INF) continue;
      int m = dd + 1 + k;
      // A fountain cluster feeds several dragons; yield only to a teammate already on it.
      if (friendDist_[h.cell] < m && friendDist_[h.cell] <= p_.hotYield) continue;
      value += p_.wHot * h.rate * fp(m);
  }
  ```
  `wHot = 2.0`, `gammaFar = 0.93`, `hotYield = 4`. A dragon yields a hot fountain **only if a teammate is already within 4 steps of it**. Distant teammates across the map do not suppress the pull. Multiple friendly dragons rush the fountain cluster together.
- **Macro Compass Navigation** ([opponents/s475/common.hpp:215](file:///D:/battlecode/BattleCode_BC/opponents/s475/common.hpp#L215), [opponents/s475/policy.hpp:402-419](file:///D:/battlecode/BattleCode_BC/opponents/s475/policy.hpp#L402-L419), [667-674](file:///D:/battlecode/BattleCode_BC/opponents/s475/policy.hpp#L667-L674)):
  On large maze maps (Trauma: 90+ tiles to fountains), discounted BFS pulls (`gammaFar^m`) decay to 0. S.4.7.5 runs one full-board BFS (`macroNav_`) to the highest rate-per-distance fountain beyond `horizon`, and scores moves with an undiscounted progress metric:
  ```cpp
  value += p_.wCompass * roomFactor * (cur - dd2);
  ```
  `wCompass = 0.05`. Dragons beeline directly through mazes toward distant fountains instead of wandering blindly.

#### Swarm Budding Uninhibited by Enemies
- **Zero Enemy Distance Barrier for Swarm** ([opponents/s475/policy.hpp:832-840](file:///D:/battlecode/BattleCode_BC/opponents/s475/policy.hpp#L832-L840)):
  In `Policy::trySplit()`:
  ```cpp
  // 7x7 vision only reaches Chebyshev distance 3, so gating every split on "no enemy
  // head anywhere in sight" (splitEnemyDist=2) means we stop budding almost entirely
  // once the board is populous ... Keep the caution for the rarer, more valuable
  // grower bud; drop it for swarm.
  if (grower_)
      for (World::Seen const& s : w_.others)
          if (isEnemy(s) && b.cheb(s.head, w_.head) <= p_.splitEnemyDist) return false;
  ```
  For swarm dragons, `splitEnemyDist` is **never checked**. Furthermore, swarm buds use `bareExit()` ([opponents/s475/policy.hpp:941-948](file:///D:/battlecode/BattleCode_BC/opponents/s475/policy.hpp#L941-L948)): just a single free neighbor tile, no flood-fill requirement.

#### Authenticated Pearl Gossip

### 3.2 How cand_y10/main.cpp Handles It

1. **Global Teammate Yielding Starves Fountain Clusters** ([cand_y10/main.cpp:927](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L927)):
   In `evaluate()`:
   ```cpp
   if (friendDist[n] < nd || (friendDist[n] == nd && friendMinId[n] < MY_ID)) p *= P.friendCloser;
   ```
   `P.friendCloser = 0.08` ([cand_y10/main.cpp:35](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L35)). If *any* teammate on the entire map is 1 step closer to a pearl bed (`friendDist[n] < nd`), the pearl probability/value is slashed by **92%** ($0.08$). Even on a 5-pearl fountain cluster in the Trophy or Devil center, only 1 dragon approaches; the rest turn away, allowing the opponent to swarm and claim the cluster.
2. **Artificial Fountain Suppression on Maze Maps (`shortSight`)** ([cand_y10/main.cpp:898](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L898), [928-930](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L928-L930)):
   ```cpp
   bool shortSight = !bigFeed && UNITS >= 3 && L <= 4 && queen.id != MY_ID && ROUND < P.mineUntil;
   // ...
   p *= shortSight ? min(P.minerFarmCap, farmBonus(n)) : farmBonus(n);
   // ...
   double v = p * (shortSight ? powM[nd] : powT[nd]);
   ```
   - On maze maps (`!bigFeed`), `shortSight` clamps `farmBonus` to `minerFarmCap = 1.5` (preventing full 3.0 fountain valuation).
   - Target pull uses `powM[nd] = pow(minerGamma, nd)` with `minerGamma = 0.90`. At distance 40–60 (Trauma/Devil), $0.90^{50} \approx 0.005$. Distant fountains exert zero navigational pull.
   - `cand_y10` has **no macro compass**. In Trauma, dragons wander local corridors blind for up to 70 rounds before stumbling onto a pearl.
3. **Early Swarm Budding Blocked by Distant Enemies** ([cand_y10/main.cpp:990](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L990), [1582](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L1582)):
   In `evaluate()`:
   ```cpp
   if ((L >= 6 || UNITS <= 4) && (dd == 1 || (dd <= 3 && dd <= er.len - 1))) adjacentThreat = true;
   ```
   And in `think()`:
   ```cpp
   bool staySafe = (opts[0].ev.pDeath < 0.5 || (MY_LEN <= 4 && ROUND < P.mineUntil)) && !opts[0].ev.adjacent;
   if (!protectedQueen() && staySafe && swarmSplit()) return;
   ```
   When `UNITS <= 4`, any enemy head within Chebyshev distance 3 triggers `adjacentThreat = true`, which sets `opts[0].ev.adjacent = true` and **completely blocks `swarmSplit()`**. In the congested centers of Trophy and Devil, dragons see enemies at distance 2–3 on rounds 5–30 and freeze budding, losing the numbers race while the opponent swarms.
4. **Zero Pearl Gossip**:
   `cand_y10` sonar messages strictly pack `QueenInfo` ([cand_y10/main.cpp:1631](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L1631)). There is no pearl or fountain gossip implementation.

### 3.3 Concrete Code Changes for cand_y10/main.cpp

1. **Change 3.1: Fountain Teammate Yield Gating (`hotYield`)**
   - **Location**: [cand_y10/main.cpp:927](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L927) in `evaluate()`.
   - **Current**:
     ```cpp
     if (friendDist[n] < nd || (friendDist[n] == nd && friendMinId[n] < MY_ID)) p *= P.friendCloser;
     ```
   - **Proposed**:
     ```cpp
     bool isFountain = (gmax[n] > 0 && gmin[n] + gmax[n] <= 24);
     bool yieldTile = (!isFountain || friendDist[n] <= 4);
     if (yieldTile && (friendDist[n] < nd || (friendDist[n] == nd && friendMinId[n] < MY_ID))) p *= P.friendCloser;
     ```
   - **Rationale**: Direct port of S.4.7.5 `hotYield = 4` ([opponents/s475/common.hpp:205](file:///D:/battlecode/BattleCode_BC/opponents/s475/common.hpp#L205)). If a cell is a high-yield fountain, teammates do not discount it unless another friendly dragon is already within 4 steps. Enables multiple dragons to contest and farm Trophy and Devil centers together.

2. **Change 3.2: Remove `minerFarmCap` Suppression on Maze Fountains**
   - **Location**: [cand_y10/main.cpp:928-930](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L928-L930) in `evaluate()`.
   - **Current**:
     ```cpp
     p *= shortSight ? min(P.minerFarmCap, farmBonus(n)) : farmBonus(n);
     fsum += p * powG[nd];
     double v = p * (shortSight ? powM[nd] : powT[nd]);
     ```
   - **Proposed**:
     ```cpp
     p *= farmBonus(n);
     fsum += p * powG[nd];
     double v = p * (shortSight && farmBonus(n) <= 1.2 ? powM[nd] : powT[nd]);
     ```
   - **Rationale**: Restores full 2.0–3.0x valuation for rapid-respawn fountains on maze maps, and prevents `minerGamma = 0.90` from extinguishing target valuation for fountains beyond tactical range.

3. **Change 3.3: Unblock Swarm Budding from Distant Enemy Interference**
   - **Location**: [cand_y10/main.cpp:990](file:///D:/battlecode/BattleCode_BC/cand_y10/main.cpp#L990) in `evaluate()`.
   - **Current**:
     ```cpp
     if ((L >= 6 || UNITS <= 4) && (dd == 1 || (dd <= 3 && dd <= er.len - 1))) adjacentThreat = true;
     ```
   - **Proposed**:
     ```cpp
     if ((L >= 6) && (dd == 1 || (dd <= 3 && dd <= er.len - 1))) adjacentThreat = true;
     else if (UNITS <= 4 && dd == 1) adjacentThreat = true;
     ```
   - **Rationale**: Ports S.4.7.5's observation that swarm budding should not be paralyzed by enemies 2–3 tiles away in 7x7 vision. Only an enemy head at immediate distance 1 (`dd == 1`) threatens budding drones when `UNITS <= 4`.
