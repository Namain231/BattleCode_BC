## What the code does today (reference: baselines/Y12_11/main.cpp; check the same spots in viper_nv30k/main.cpp)
- The move score is driven by a pearl FIELD: pearlProb(c, T) (line ~512) gives the probability a pearl is on cell c when we arrive at round T; never-seen cells get `explScale * min(0.22, 0.04 + T/1500)` (EXPL31; explScale set per turn around line 2021: explLate 0.5 after r120 or 60% seen, times explSolo 0.4 when no ally within 6). `seenR[c]` is the last round the cell was SEEN (the 7x7 view), not walked, so cells in view look 'explored' even if the dragon never goes there.
- PEXPLORE (lines ~1027, 1197, 1229, 2030-2050, 2335-2345): only for small drones (L<=4) on UNKNOWN maps (!KM) that have not grown for 12 rounds; they head to the nearest seen cell with an unexplored portal edge. - STUCK36 bans a target chased 15 rounds without growth. There is NO per-dragon visit memory, so nothing discourages retracing.

## Design (implement behind Params flags; `hunger` master flag default ON in viper_nv30h)
Per dragon (each dragon is its own process): `lastEat` = last round its length grew or it ate a pearl (use the same growth detection as pxLastGrow2; reset on birth and after a split so children start fed); `h = clamp((ROUND - lastEat - grace) / ramp, 0, 1)`.
Separate parameter pairs for NON-QUEEN (miners/drones) and QUEEN, e.g. Params: hungerGraceN=8, hungerRampN=40, hungerGraceQ=15, hungerRampQ=60, plus weights below; all tunable, documented.
Effects, scaled by h:
1. Exploration prior (non-queen): multiply the never-seen / long-unseen term in pearlProb by (1 + hungerExplN*h) (cap x4) and ALSO raise the value of cells not WALKED recently (see 2), so food-less regions beyond the current patch pull harder.
2. Visit memory + anti-retrace: keep a per-dragon `visitR[c]` (last round the HEAD was on c; optionally 1-cell dilation). Penalty on option paths that land on or cross cells visited in the last K=30 rounds, weight hungerRevisitN*h (queen: smaller, hungerRevisitQ*h). Retracing a path just walked costs more the hungrier the dragon is. Never make a move illegal; it is a score term only.
3. Frontier pull (non-queen): generalise PEXPLORE: a target = the nearest known-passable cell next to an unseen/unwalked region (BFS over known cells; ties broken by hash of id so allies spread out), sticky for ~8 rounds, dropped when reached or after a STUCK-like timeout; score += hungerFrontierN*h*(dist_before - dist_after), same pattern as line 1197. Applies on known AND unknown maps (the KM restriction of PEXPLORE is removed for this term), all lengths <= hungerMaxLenN (default 6); portal crossings stay governed by the existing PEXPLORE rules (do not loosen safety).
4. QUEEN rules (different, conservative): only when no enemy head within 8 and phase is outgrow (or before r150): grace 15 / ramp 60, cap h<=0.6; effects = anti-retrace (2) with a small weight and a mild exploration prior (1) limited to cells inside regions that the existing trap/corridor logic ('queen avoids corridor cells', QHUNT enemy reach) considers safe; NO portal crossings, NO frontier chase through unknown/narrow terrain. In PROTECT/CONSERVE/ELIM phases hunger is OFF for the queen.
5. Safety invariants: do not touch the survival veto / doomed logic / QHUNT / guards; hunger never overrides safeClass; CPU: add O(cells) work only once per turn (BFS for the frontier target at most every 4 turns), peak CPU <= 66M on australia and around_unsw.
Keep indicators bland (short tag only when a frontier target is active).
